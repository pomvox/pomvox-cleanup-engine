# Prompt for the Pomvox app integration

Integrate Pomvox Cleanup SDK `0.1.0-beta.2` into the Pomvox app. Read the SDK's `docs/integration-gap-review.md`, `docs/contract.md`, and `Examples/PomvoxAdapter/PomvoxCleanupAdapter.swift` first. Implement and test the integration, rather than only writing another gaps document. Keep audio/STT, UI, dictionary transforms, history, clipboard and insertion in the app.

1. Add the public Swift package `https://github.com/pomvox/pomvox-cleanup-mlx.git` at exact version `0.1.0-beta.2` and select the `PomvoxCleanupMLX` product. It pulls the matching `pomvox-cleanup-engine` core version automatically. Build through Xcode so Metal resources are packaged. Replace the previous cleanup SDK path/submodule dependency rather than linking a second copy of `PomvoxCleanupMLX` or `PomvoxCleanup`. Verify that existing MLX dependency constraints still intersect; do not silently change unrelated pins. No submodule is required for the published package. `Runtime/MLX` inside the core repository is the development source layout, not a remote package URL. If deliberately testing unreleased changes, reference that local development package and report its dirty state. Preserve the app's other dependency pins and CI configuration.

2. Replace the duplicate installer with `PackInstaller.install(snapshot:manifestData:destination:)` on a background task. Bundle the SDK's trusted pinned `packs/simplewords-v3/pack.json`; acquire the corresponding licensed snapshot explicitly in the host. Do not derive trust from snapshot-provided manifest bytes. Install in Application Support, keep the installation immutable, and verify/reuse an existing installation rather than overwriting it. Installer follows source snapshot symlinks and publishes independent regular files; APFS can share their storage by cloning. The returned `ValidatedPack` can be passed to `.validated(installedPack)` for the first open, avoiding an immediate duplicate hash pass.

3. Own a single shared preparation task and cleaner in a serialized backend state machine. Start preparation when local cleanup is enabled/armed, not after a 20-second timer. Concurrent callers await the same task. Use `Cleaner.open(pack: .directory(url), runtime: .mlx(vocabulary: selectedTerms), policy: .local)`. Select a stable ordered vocabulary with at most 64 nonempty terms, each at most 128 UTF-8 bytes and no line breaks, and at most 2,048 bytes total. Report omitted terms as counts without logging their contents. Pass this selected vocabulary in **every** `CleanupRequest`; configuring the factory prepares a cache, not default request vocabulary. Keep the complete dictionary for the host's later transform. Dictionary changes naturally replace the single prefix on the next request.

4. Track an utterance generation/session identifier. Cancellation or supersession cancels the cleanup waiter and suppresses insertion, including cancellation during shared preparation. A single utterance cancel must not accidentally cancel preparation needed by others. Implement cancellable, deadline-bounded waiters around the shared preparation task: awaiting an unstructured task's `.value` alone does not stop waiting when the waiter is canceled. Do not use a task-group race whose canceled child keeps awaiting that value, because leaving the group would still wait for preparation. If cleanup is disabled or the backend is retired during open, close any late-created cleaner and discard it instead of publishing it into the new state. Recheck task cancellation and session identity after all host transforms, immediately before synchronous insertion on the owning actor. A synchronous transform callback can retire the session even without an await; a check only before transforms is insufficient. Never convert CancellationError into raw insertion. SDK deadlines cover admitted request work, not open: bound the whole host operation separately and pass a positive remaining budget of at most 60 seconds. Never repeatedly reset the budget while waiting or retrying. If no budget remains, skip cleanup and apply the host's explicit fallback policy only after checking that the utterance is still current; do not submit a zero or negative deadline.

5. Use result.text for cleaned/unchanged outcomes. For fallback, preserve the original transcript exactly at the cleanup boundary and record its reason. Preserve the established host pipeline exactly once: SDK cleanup/evaluation → spoken formatting → dictionary → signature → insertion. Remove the app's second `acceptOutput` pass for SDK results. Retain the original transcript for UTF-8 edit mapping; use SDK UTF-16 conversion for editor ranges. Treat setup/invalid-request errors separately from runtime fallback and expose configuration failures honestly. Requests accept at most 16,384 UTF-8 bytes of transcript: detect larger input before calling the SDK and preserve the entire original transcript through the host's explicit unsupported-length fallback. Do not truncate or invent automatic chunking. Never switch a local request to cloud processing on failure.

6. On memory pressure/idle eviction, stop new admission through the backend state machine, retain `cleaner.pack`, and await `try await cleaner.closeAndWait()` before opening a replacement with `.validated(savedPack)`. Coalesce overlapping eviction/reopen requests. Stay evicted until cleanup is needed and the host memory policy permits reopening; do not immediately reopen in response to the same memory-pressure event. A canceled retirement waiter must leave a tracked retiring cleaner that the next opener waits for. Canceling the wait does not release a stuck worker or authorize another model. Changed pack identity requires fresh `.directory` validation. Never reuse this handle across process launches. Resume still reloads weights and warms the prefix; do not label it a zero-cost resume. Preserve the selected vocabulary and runtime policy on every reopen. By default the runtime does not clear MLX's shared buffer pool: releasing model references does not guarantee an immediate RSS drop. Choose `clearBufferCache: true` only if the host deliberately accepts process-global clearing at every generation and close; validate actual memory-pressure behavior with other MLX workloads.

7. Use `await cleaner.availability` to distinguish quarantine from ordinary work or closed state. It is a snapshot, not a reservation. Optionally wait briefly, cancellably, within the original remaining utterance budget for quarantine to clear, then make one cleanup attempt; otherwise use the existing explicit raw fallback policy. Never open a second model to bypass quarantine. Recovery has no guaranteed maximum duration.

8. Record only observed metrics: preparation separately from request total, optional tokenization/prefill/inference, `prefixCacheUsed`, prompt/decode tokens and speculative counters. Compute speculative acceptance only when drafted tokens are positive. Preserve `rejectedBy:<reason>` warnings. Nil means unknown, not zero or cached. Timeouts can finish before final generation metrics exist. Do not log transcript text, model candidates or vocabulary by default.

9. Use `cleaner.pack.manifest.capabilities` and `CleanupLogic.rulesVersion` for capability/rules reporting. This baseline supports vocabulary, English, and the frozen prompt only. Hide/disable style and speculative controls for the SDK backend. Disable model-based dictionary-variant suggestions while using it; do not secretly retain a second model. Keep ordinary dictionary editing functional. Do not claim arbitrary long dictations or implicit shopping-list formatting are fixed: the output ceiling is 1,024 tokens and conservative list guards remain.

10. Add integration tests for eager/shared preparation; a dictation racing open; session supersession; cancellation before/during/after inference; no insertion from stale results; transform order and exactly-once application; dictionary change/cache reuse; invalid/bounded vocabulary; rejected diagnostics; timeout/quarantine recovery; memory pressure and close/reopen races; changed installed files; sleep/wake; disabling or retiring the backend during open; cancellation of a preparation waiter without canceling shared preparation; explicit remaining budgets on long inputs; composed/decomposed Unicode dictionary changes; and unavailable auxiliary controls. Run the existing public behavior corpus and non-repetitive long-input cases, recording all outcomes. Run real dictation with concurrent STT and a repeated-session soak. Keep private history outside the repository. Measure cold startup, warm cleanup with 0/1/2/64 terms, and reopen latency independently under comparable load.

Deliver code, relevant test/build results, remaining concrete blockers, and before/after screenshots for changed UI controls. Do not declare production readiness from SDK unit tests alone or invent support for missing APIs. Do not push, publish, or change CI unless separately requested.
