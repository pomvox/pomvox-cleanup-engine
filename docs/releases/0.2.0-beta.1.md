# Pomvox Cleanup SDK 0.2.0-beta.1

Public **beta** release of the local-first Swift cleanup SDK. It adds speaker-attributed transcripts, deterministic notes, an optional local diarizer, explicit cloud clients for diarization and notes, and an iOS 17 build target. The dictation path and default cleanup behaviour are unchanged. `0.1.0-beta.3` was prepared but never tagged; its changes ([notes](0.1.0-beta.3.md)) ship here for the first time.

## Install from GitHub

- Core/cloud: `https://github.com/pomvox/pomvox-cleanup-engine.git`, exact version `0.2.0-beta.1`; products `PomvoxCleanup`, `PomvoxNotes`, `PomvoxDiarization` and `PomvoxCleanupCloud`.
- Apple Silicon inference: `https://github.com/pomvox/pomvox-cleanup-mlx.git`, exact version `0.2.0-beta.1`; product `PomvoxCleanupMLX`. It pulls the matching core version automatically. Add it through Xcode so Metal resources are packaged.
- Local diarizer: `PomvoxDiarizationFluid` lives in `Runtime/Diarization` in the core repository and is **not yet published as a remote package** (#25). Use it from a checkout of the `v0.2.0-beta.1` tag as a local package.

Both published packages are public and MIT licensed. Swift 6 is required, with macOS 14+ or iOS 17+. Local inference also requires the separately obtained pinned model snapshot.

## Changes

Speaker transcripts and notes: `Transcript`, `SpeakerTurn` and `Transcript.attribute(words:segments:)` align host STT words with diarizer segments. `clean(_ transcript:options:)` cleans one turn per ordinary request and preserves speakers, spans and order. A turn the model never sees keeps its exact bytes with a named warning. `PomvoxNotes` derives participants and quoted action-item, decision, question and list-item candidates with turn index and UTF-8 range; no model writes them. See `docs/speaker-notes.md`.

Long recordings: `cleanIncrementally(_:options:resuming:)` yields each turn as it finishes and resumes from a host-saved `TranscriptCheckpoint`. The checkpoint is refused unless the transcript bytes, speakers, spans, output-affecting options, pack and accepted results all match. Opt-in `TurnSegmentation` splits turns longer than 1,000 bytes (default) at sentence ends into requests that fit the 1,024-token output cap, then reassembles one `TurnResult` with per-segment source and output ranges (#13). A timed-out turn no longer makes the following turns fall back at once as `unavailable`.

Diarization: the dependency-free `PomvoxDiarization` contract and a verified diarizer pack format; the optional `FluidDiarizer` over FluidAudio 0.15.5's offline pyannote community-1 pipeline, loading only from a hash-checked pack and never downloading; `closeAndWait()` on every diarizer. A diarization that is already running cannot be interrupted (#34): cancellation returns to the caller at once, and the models are released when the pipeline ends.

Cloud, explicit only: `CloudDiarizer` and `CloudNotes` follow `CloudCleaner`'s posture (endpoint and credentials required, HTTPS or loopback, no redirects, no retries, one request in flight). Their wire protocols are in `docs/cloud.md`. No provider is selected, and nothing local routes to cloud.

iOS: all three packages declare `.iOS(.v17)`, the floor set by mlx-swift-lm, swift-tokenizers and FluidAudio. An iOS 17 app links every library with no deployment-target override; `Examples/iOSConsumer` and a CI job check that build. `import PomvoxNotes` and `import PomvoxDiarization` now compile as documented.

Compatibility: new protocol requirements (`Cleaning.packIdentity`, `Cleaning.availability`, `Diarizing.closeAndWait()`) have default implementations, so existing conformers still compile. `TurnResult` gains an optional `segments` field and keeps its existing initializer. The cleanup wire protocol, prompt, tokenizer, decoding, admission limit, output cap and pinned packs are unchanged. The MLX runtime source differs from beta.2 only in its platform declaration.

## Read before adopting

This is a beta, not a production-stable release. **iOS is a build target, not a validated platform**: nothing has run on an iPhone here. Model load, memory, thermal and background behaviour are not measured, and the pinned 8-bit `simplewords-v3` pack is sized for a Mac (#30, #2). `docs/ios-validation.md` is the device checklist; its results matrix is empty. The diarizer's quality is checked only on synthetic speech (#28).

The model host requires access-condition acceptance. We do not redistribute weights or promise anonymous model downloads. SDK package installation and model acquisition are separate steps. English and bounded vocabulary are supported. Context/style, auxiliary generation, Intel inference and automatic cloud fallback are unsupported. A still-running canceled worker keeps its resources until it returns.

Real Pomvox microphone/STT integration, sleep/wake and memory-pressure validation, a reviewed quality corpus, a complete supported-platform matrix and an archived model-license record remain stable-production release gates. See `docs/testing.md`.
